# Learnings harvested from the Hisense A6L LineageOS 24 port

Status (2026-10-13): research, mostly acted on the same day (§0). Nothing on the phone was written; all on-phone checks were read-only
(`adb shell` / `su -c` reads). Items marked **[checked]** were re-measured by the main session on our own
firmware or the live phone today; everything else comes from five read-only subagent passes and should be
treated as a lead until checked.

Source: [PaddleStroke/hisense-a6l-lineageos](https://github.com/PaddleStroke/hisense-a6l-lineageos)
(HEAD `ede802b`, 2026-10-13, project paused). Hisense A6L / HLTE730T: SDM660, stock Android 9, kernel 4.4,
A-only eMMC, rear e-ink secondary panel. They replaced the whole vendor side (mainline Linux 7.2.3, Mesa,
libcamera, own HALs) on top of `lineage_gsi_arm64` (`lineage-24.0`, `cp2a`). A6L paths below are relative to
that repo.

**Bottom line.** None of their device code is reusable, and the repo has no images. What carries over is
(1) Hisense-common bootloader and e-ink software facts, (2) Android 17 requirements, and (3) flashing and
logging methods. Several A6L techniques, applied to our own dumps, turned up new facts about the A9 itself.

## 1. New facts about the A9 (found by applying A6L methods to our files)

| # | Finding | Evidence | Status |
|---|---|---|---|
| 1.1 | **ABL is LZMA-compressed, not encrypted.** UEFI FV at 0x3000 in `abl.elf`, LZMA GUID section → 491,720-byte PE, all strings readable with Python `lzma`. The a9-device skill row "abl.elf strings: Encrypted, entropy 7.95" is wrong. | decompressed copies in session scratchpad | **[checked]** |
| 1.2 | **The phone's bootloader chain is newer than `HLTE556N/` (.04.06.00).** Golden `abl_a`=`abl_b` (`fbe6beaa…` over 159,744 B) ≠ package `abl.elf` (`9529ca83…`); ABL build date **Dec 28 2022** vs **Jul 13 2022** (same date as the running kernel `4.19.157-perf`). xbl/tz/devcfg/imagefv/xbl_config also differ (subagent). A full package flash would downgrade the boot chain (anti-rollback risk). | golden dump vs package | **[checked]** (abl) |
| 1.3 | **Unlock flags live in the plain `devinfo` partition**: bytes 13/14 = `01 01`. On the A6L they are in protected storage. Writing an old/locked devinfo would very likely relock the phone → "device is corrupt" with custom images. `rawprogram4.xml` leaves devinfo unwritten (good). | `lun4/devinfo.bin` | **[checked]** |
| 1.4 | **The A9 ABL has three `Hisense` sub-commands, the same code as the A6L.** Handler at RVA 0x34dac in the phone's `abl_a` LinuxLoader: exact `AsciiStrnCmp` (length includes the NUL) against `" unlock"` (8), `" lock"` (6), `" unlockallow"` (13). `unlock` and `lock` both call RVA 0x24c90, which writes devinfo +0x0d and +0x0e (unlocked, critical unlocked) to 1 or 0 directly: no volume-key prompt, no wipe. `unlockallow` takes a separate path. The Hisense client's help lists only `unlockallow`, so `unlock`/`lock` are undocumented. The user unlocked with `Hisense unlock` (user report, matches the disassembly). An earlier string-only reading in this doc wrongly said the A9 verb was `unlockallow`. **`Hisense lock` relocks with no prompt; with custom images flashed that is a likely "device is corrupt". Add it to the NEVER list.** | capstone disassembly of `abl_a` (session scratchpad `re/`) | **[checked]** |
| 1.5 | **ABL fastboot table has no `boot`, no `oem edl`.** Settles the A9Toolkit `oem edl` claim. Has `snapshot-update [cancel]` + `getvar snapshot-update-status` (VAB merge control: a sanctioned alternative to touching misc). | ABL strings | **[checked]** |
| 1.5b | **The ABL supports Pixel-style custom AVB keys and yellow state** (`flashing avb_custom_key`, `StoreUserKey`/`GetUserKey`, `ValidateVbmetaPublicKey ... UserKey %d`, `yellow`). Relocking with our own key would need a fresh `/data` (state reset, and a changed root of trust for the wrapped FBE keys, inferred). **Not pursued: user decision 2026-10-13.** Rule 14 (never relock) stands. Also measured: the ABL is signed (hash/signature segment with cert chain) and the kernel has no kexec, so `fastboot boot` cannot be added; the substitute is a try-boot on slot B. | ABL strings and ELF headers, `/proc/config.gz` | **[checked]** |
| 1.6 | **Hisense persistent log partition `kdebuginfo` (sda9, ext4, 200 MiB) is not written under the GSI.** It holds per-boot `kmonlog_*` (XBL+ABL+kernel log to ~100 s), `power_reason.txt`, `/edpd/bitmap_low.raw`. Last write 10 Aug 2026 (when stock `/system` went). Stock mounted it via `vendor.kdebuginfo.mountfs` and `init.hmct.rc` (system side, gone). Live: not mounted, prop empty. | `debugfs -c` on golden `lun0/kdebuginfo.bin`; live `mount` | **[checked]** |
| 1.7 | **pstore will stay empty: warm reset is compiled out.** `# CONFIG_SUPPORT_WARM_RESET is not set`; every boot log shows `HARD_RESET by PS_HOLD`, `Warm reset: 0`. Do not invest in ramoops. `CONFIG_RS_RECORDER_SUPPORT=y`, `CONFIG_HS_POWERON_REASON=y`, `CONFIG_HISENSE_BOOTLOADER_LOG=y`. | live `/proc/config.gz` | **[checked]** |
| 1.8 | **ABL reads Hisense flags from `diag`** (factory record, "LCD: Eink epd 824x1648", debug/dev flag bitmaps, `arrest_recovery`, `encrypt` tag) and passes `androidboot.eink_vcom=` (2730 on our boots). Per-device provisioning: never write it. | ABL strings, golden `lun0/diag.bin` | subagent |
| 1.9 | `lpm_levels.sleep_disabled=1` is on the boot cmdline, but the vendor clears it: live value **`N`**. The A6L's "cores spin in idle" drain does not apply. | live sysfs | **[checked]** |
| 1.10 | Vendor init disables UBWC when the EPD exists (`vendor.gralloc.disable_ubwc=1`). If a gralloc change ever re-enables UBWC, suspect garbled e-ink input. | vendor rc (subagent), live prop = 1 | **[checked]** (prop) |
| 1.11 | Hisense persist layout confirmed: `wlan_mac.bin` (`Intf0..3MacAddress=`), `stk3b6x` ALS calibration, `keybox_verify.txt`. Adaptive brightness likely depends on persist (inferred). Already covered by rule 6. | `Backups/2026-08-08_055553/persist.img` | subagent |

## 2. LOS 24 on the A9: what the evidence says

LOS 24 shipped 2026-10-12; no LOS 24 GSI exists yet (web search 2026-10-13). The A6L never ran A17 on an
old kernel or old vendor: they rejected that and self-built everything. Our blockers, most likely first:

1. **VNDK 30.** A plain `lineage_gsi_arm64` on 24.0 ships VNDK 31–34 only (A6L `docs/build-checkpoint.md:17-19`).
   Ours ships v28–v34 and the vendor is `ro.vndk.version=30` **[checked]**. Any LOS 24 base must carry
   `com.android.vndk.v30` (TrebleDroid legacy-VNDK patches). Check with
   `debugfs -R "ls /system/system_ext/apex" <img> | grep vndk` before flashing.
2. **Framework compatibility matrix 5 is gone.** lineage-24.0 builds FCM 7, 8, 202404+; lineage-23.2 still has
   5 and 6 **[checked]**. Our vendor manifest is `target-level="5"` **[checked]**. Effect on a GSI at runtime
   is unmeasured (may only fail OTA-time VINTF checks, may drop HIDL client support). The worst case is
   keystore2 / HIDL keymaster: our `/data` uses wrapped keys, so there is no software-KeyMint fallback like
   the A6L used. Test only on slot B with a wipe planned.
3. **NetBpfLoad kernel gate.** lineage-24.0 requires 5.10 at 25Q4/26Q2 and 5.15 at 26Q4, `reboot_on_failure`.
   Our 25Q4 GSI loads BPF on 4.19 (`bpf.progs_loaded=1`) **[checked]**, so the base patches or exempts it.
   The loader is in the Tethering mainline APEX: a Play update could replace a patched loader. **Never remove
   `netbpfload.rc`**: system_server's libmemevents aborts without it (A6L `docs/android-framework-v48-20260918.md:77-81`).
4. **Framework NPEs from incomplete forward-ports.** Example: HintManagerService with no AIDL IPower (LOS
   change 434585 missing from early 24.0). Ours has the AIDL `IPower` service **[checked]**, so this one is
   unlikely.
5. **Our smali patcher on SDK 37.** The A6L has no notes on A16→A17 smali shape changes. The zero-match report
   is the only safety net. Add an SDK 37 / `CP2A` base check. After a `services.jar` edit, dependent ODEX
   files go stale (27 changed checksums in their build): verify the patcher deletes or regenerates them.
6. **Self-building is heavy:** Soong was OOM-killed at 48 GB RAM + 16 GB swap until `GOMEMLIMIT=36GiB` was
   forwarded (`tools/soong-memory.patch`). `systemimage` took 3h41m; sync ~136 GiB. A GitHub-hosted runner
   cannot do it. The realistic path is to wait for a TrebleDroid-based LOS 24 GSI and patch it.

Other A17 notes: Bluetooth profiles default off unless `bluetooth.profile.*` props are set, and cp2a routes SCO
through audio (`sco_managed_by_audio`): check HFP calls on a test build. GApps for A17: MindTheGapps
`17.0.0-arm64`. Google "Copy apps & data" crash-loops in setup while USB is plugged in (relevant to
`a9-los-setup`). Lineage *userdebug* is not `ro.debuggable=1`.

## 3. E Ink: the A9 runs the same Hisense stack, a newer generation

The subagent's offline greps of our stock system/vendor and `librecovery_ui.so` found
`com.hmct.epd.IEpdManager`, `EpdManagerService`, the same mode strings (`typing:1 picture:2 reading:3 fast:6
video:8`), `forceClearGhosting`, `ModeDecision_MirrorMode`, `Init_Eink_SWTcon`. It is not byte-identical:
`Init_Eink_SWTcon` takes 3 args on the A9 vs 6 on the A6L; `Update_epd_Image` vs `Update_Display_Image`;
lib version 2.0 vs 2.2. Semantics probably carry; offsets and argument lists must be re-derived.

## 4. Flashing and recovery methods to adopt

From the A6L tooling (process subagent), ranked:

1. **We have no flash script.** Test-flash to B and promotion to A are hand-typed from
   `slots-and-promotion.md`. Write `flash-test-b.sh` / `promote-b-to-a.sh`: health first, sha256 against the
   `.sha256`, `is-userspace` + `current-slot` before each write, super free-space check, default check-only.
2. **Readback plus invariants.** After boot, hash the written partitions as root and compare with the image;
   hash `persist`, `fsg`, GPT before and after (not modemst: the modem rewrites it). `restore-golden.sh` writes
   with `edl w` and never reads back.
3. **Keep-data compatibility check** (`tools/Make-RomUpdateCompat.py`): compare the image's platform cert from
   `plat_mac_permissions.xml`, SDK and security patch with the running system. This automates our
   crDroid-key vs testkey `/data` trap.
4. **Image diff before flashing:** file-level diff of new vs previous image with an expected-change list. It
   would have shown the v4/v5 overlay regressions.
5. **EDL write guard:** label and range denylist in `edl-cli.sh`: persist, modemst1/2, fsg, fsc, **devinfo**,
   **diag**, xbl/abl/tz, GPT LBAs.
6. **Device pinning:** pin `A9_SERIAL` (now read from gitignored `local/device.json`); `a9_in_edl` should require exactly one 9008 device.
   `restore-golden.sh` runs `adb reboot edl` without a serial.
7. **One USB operation at a time:** `flock` in `a9-env.sh`.
8. **Per-run capture dirs** with argv, exit code, git HEAD, health before/after. `restore-golden.sh` logs to
   `/tmp` and retries overwrite the evidence.
9. **Fake `adb`/`fastboot`/`edl` stubs** for offline tests of our scripts (`ADB`/`FB`/`EDL` are already
   overridable).
10. **Golden lags main:** after a promotion, warn when the written hashes no longer match golden `SHA256SUMS`.
11. Unicorn emulation of the real ABL's header/DTBO/AVB code (`tools/Test-CapturedAbl*.py`) is now feasible
    given 1.1. It would have caught the missing `recovery_dtbo` of TWRP builds 1–2 offline.

Traps worth one line each: `adb exec-in 'dd of=…'` truncates (toybox dd has no `iflag=fullblock`): push
plus on-phone hash instead. `pkill -f` matches itself. `adb shell` inside piped `bash -s` eats stdin.
Firehose `edl reset --resetmode=edl` might give a fresh Sahara hello without a human (untested; try once,
attended, at the end of a healthy session).

## 5. Logging that would make the A9 debuggable

- Mount `kdebuginfo` (1.6) from a Magisk service at `/mnt/kdebuginfo` and append `dmesg -w`, PON lines,
  `/proc/cmdline` and `sys.boot.reason` per boot with fsync. Do not format it. The A6L alternative was a
  CRC-slotted ring in `/metadata` (`device/hisense/a6l/rom/debug/a6l-log-ring.c`). Ours is riskier there
  because `/metadata` holds the `dm-default-key` state.
- PON decoding: on the A9 a normal reboot is SID0 "Hard Reset" / PS_HOLD, so "Hard Reset" is not abnormal.
  Hisense `power_reason.txt` shows `SMPL` for boots whose PON registers have no SMPL bit: don't trust that label.
- A panic most likely lands in Qualcomm crashdump mode (`05c6:900e`, `set_dload_mode=1` in kmsg), inferred.
  Treat a 900E "diag" state in `a9-health.sh` as a possible panic and record it before holding Power.
- Drain method: reset batterystats at unplug; next morning collect batterystats, `/sys/power/suspend_stats`,
  wakeup sources, screen-off awake share. Their e-ink minute clock woke the phone 590 times a night; our
  overlay AOD is the same pattern. We have no drain data yet.

## 7. Anti-patterns seen in the A6L repo

- Per-version tool copies (V37…V75U): 948 files archived on the last day. Use flags and git hashes instead.
- Append-only handoff/TODO docs (1,208 and 1,887 lines of stacked "Latest" banners). We show early signs.
- An agent-written handoff granting itself standing flash permission. Authorization stays in user-owned text.
- A file-drop relay that runs any dropped `*.sh` outside the permission system.
- Load-bearing helpers in `/tmp`; one armed hardware run failed on an unstaged helper.
- Token-squeezed prose ("workerexit0").
- Twelve review rounds on one day with findings dropping to 1 per round.
