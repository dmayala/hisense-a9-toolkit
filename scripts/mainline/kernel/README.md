# A9 mainline kernel: patch series, config, initramfs

2026-10-14, revised 2026-10-15. Status: builds offline, image passes `scripts/abl-check.sh` for both routes
(recovery, and boot + null dtbo). Booted once without approval (2026-10-15): reset loop on the misc BCB, no USB.
**First boots only through `scripts/mainline/first-boot.sh`** (human-run; docs/mainline-kernel-build.md §4).
Full write-up, safety rationale and the proposed first boot: [docs/mainline-kernel-build.md](../../../docs/mainline-kernel-build.md).

Base: linux **v7.2.10** (stable, shallow clone). Build: `scripts/mainline/kernel/build.sh` (all | kernel | image | check),
under `~/A9-build/mainline` (local disk, never `$A9_DATA`). Toolchain: `shell.nix` (nixpkgs aarch64 cross gcc 14).

The patches are generated from commits in the build tree: edit there, then
`git -C ~/A9-build/mainline/linux-7.2.10 format-patch -3 --no-signature -o scripts/mainline/kernel/patches`.

The `0061` CRTC fence patch backports André Draszik's paired July 2026 fixes:
remove the ops-identity BUG_ON from the fence name callbacks and wait an RCU
grace period in `drm_crtc_cleanup()`. Since dma-fence detaches ops on signal,
a concurrent `SYNC_IOC_FILE_INFO` can otherwise panic in either callback.
Sources: [race fix](https://lore.kernel.org/all/20260721-linux-drm_crtc_fix2-v3-2-afa8c71506e6@linaro.org/)
and [teardown lifetime fix](https://lore.kernel.org/all/20260721-linux-drm_crtc_fix2-v3-1-afa8c71506e6@linaro.org/).
The backport changes no public structures, exports or fence signaling behavior.
