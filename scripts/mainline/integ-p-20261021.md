# INTEG-P: default suspend fixes on O3-FBE

Host-only integration for agent, on `integ/20261021o3-fbe` e8adf1b.
The supplied R21j phone proof is six Android-driven suspend cycles with
FBE/enforcing/Wi-Fi/ADSP/modem/sensors. This integration does not perform a
phone test or infer qualification of the new combined artifacts.

O3-FBE already contains equivalents of 69285d9 (clean FastRPC restore patch)
and 1a82b6e (cached SOC). The clean USB patch 3163134 and battery notification
fix 54d6fc7 are added. The FastRPC gate, ownership, disconnect and module-lifetime
semantics remain. Battery and a9-usb remain one pmi632-battery.ko, version r21g.
No permanent BT UART wake-disable is introduced.

The S1 module-only and full-build modes now apply restore immediately after
the S1 gate. The refresh-module path does the same. Their source receipts
include the restore patch hash. The default suspend kernel recipe breaks its
private USB/FastRPC source links before applying clean patches with
`git apply --unidiff-zero`; it rebuilds FastRPC using private M= objects and
stages that module into both overlay and snapshot. USB is built into Image.gz.
The normal battery recipe already copies the current source and needs no
second standalone USB power-supply module.

The new image recipe uses the frozen N kernel scratch archive read-only and
fresh private source/objects. It preserves O3-FBE's entire config, including
VT_CONSOLE=n, regulator/MSM fixes and existing PM configuration. Only the clean
USB source changes the built-in kernel. The clean FastRPC module and current
battery module are rebuilt against that kernel, then staged onto the actual
O3-FBE vendor. All 98 other modules and every non-module/non-hash vendor file
remain identical. No vendor restaging or policy/data reinterpretation occurs.
The O3 sensor firmware-copy fix and quiet printk=1 startup remain intact.

The boot retains the O3-FBE ramdisk, second, embedded recovery_dtbo, DTB and
both command-line fields. **qcom_wdt.a9_guard=1 is retained at agent's explicit
request**; the guard-0 R22b experiment is separate. This is the current test
image setting, not a claim that the watchdog is a normal sleep default.
The R20 diagnostic USB messages are not in the clean source.

From this frozen worktree, run the recipe phases in order:

```sh
python3 -I scripts/mainline/integ-p-20261021.py prepare
python3 -I scripts/mainline/integ-p-20261021.py kernel
python3 -I scripts/mainline/integ-p-20261021.py modules
python3 -I scripts/mainline/integ-p-20261021.py package
python3 -I scripts/mainline/integ-p-20261021.py verify
```

Use a fresh output at `/home/user/A9-build/mainline/integrated-20261021p`.
The intake `lp-fit-input.json` records the cached host LP-write capacity and
must accompany the build; the recipe verifies the new image fits it. The
vendor image retains the baseline's 847532032-byte size. The existing launcher
still performs its actual owned phone preflight; no worker LP-write command
or phone geometry query is run. Preserve at least 2GiB reserve plus the phase
budgets. Do not delete other owners' scratch to make room.

The output includes exact hashes, full vendor file/delta readback, actual
100-module CRC/vermagic audit against fresh built-in and shipped module
exports, e2fsck, and exact-boot ABL boot/recovery receipts. Data/FBE/SELinux
remain byte-identical to O3-FBE. Use the copied `direct-b-fbe.sh` and
`keeper-fbe.sh`; only their output/keeper paths change. `boot-command.txt`
contains the vendor-bound LP code. There is no format step. agent retains
phone, keeper and return-to-A custody.

Final artifacts and host validation are reported in
`/home/user/A9-build/mainline/integrated-20261021p/report.md`.
