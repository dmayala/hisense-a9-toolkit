# INTEG-O3-FBE

Host-only derivative of O3 vendor `4d29d46b`, retaining boot `09bb30c4`.
The signed storage FBE commit b33d7b9 is cherry-picked as 7338f40 onto O3
0433c78. The plain O3 output and storage worker's N-based POC are separate.

Build and verify with `python3 -I scripts/mainline/integ-o3-fbe-20261021.py`.
This applies `storage-row29/data/integrate.py --data-mode row29-fbe` last,
using O3's kernel.config and the matching V8 GSI policy cache. It links the
current O3 vendor CIL plus the volatile hold policy, preserving the sensor and
Wi-Fi ROW29 access grants. Exactly eight of 935 regular vendor files change;
O3's sensor fix, data guard, firmware and 100 modules remain byte-identical.
O3's boot/config/DTBO and the 6200-import CRC/vermagic proof are retained.
ABL boot and recovery PASS receipts are inherited after checking the exact
boot hash and matching DTBO; no new ABL execution is claimed.

Output: `/home/user/A9-build/mainline/integrated-20261021o3-fbe`.
`validation.json`, `vendor-delta.json`, `policy-access.json`, `fbe-tests.log`
and `integration-tests.log` record the final-image checks. The host policy
queries use a copy omitting only the unsupported functionfs_seclabel capability
descriptor for host libsepol 3.8. Production retains it. This does not establish
phone FBE acceptance.

For agent, after the current owner's return to healthy A, run the existing
read-only lp-write check on this vendor and require no resize. The no-resize
code and exact command are in `boot-command.txt`. `direct-b-fbe.sh` is a copy
of the existing direct-B launcher with only its keeper path and evidence
directory changed. It starts this package's `keeper-fbe.sh` and records its PID
in `phone/keeper.pid`. The launcher has been prepared and syntax checked only.
Retire only the identified owned previous keeper through the existing return
sequence; never run the legacy and FBE keepers together. The FBE hold is
`/dev/a9-row29-hold/stay`; timers, freshness and cap are unchanged.

The row29 extent is already FBE-formatted per agent. This package needs no
format. It retains software fscrypt v2 AES-XTS/CTS without metadata encryption
or wrapped keys. Use `tools/check-fbe.sh` through the existing root-shell
transport after boot: `set -- check` for read-only policy/key-status checking,
or the storage worker's explicit create/second-boot verify workflow for public
CE/DE markers. See `storage-row29/data/fbe/README.md` for that workflow. Its
N-based image and boot instructions do not replace this O3 pair. The formatter
is separate and must not be invoked during this handoff.

No phone access, active checkout edits, push or reviewer was used.
